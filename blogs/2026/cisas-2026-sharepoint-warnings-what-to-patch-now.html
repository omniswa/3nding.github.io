CISA's 2026 SharePoint Warnings: What to Patch Now

July 18, 2026 6-Minute Read

The Short Answer, Because You Don’t Have Time For a History Lesson

If you run on-premises Microsoft SharePoint Server, CISA wants you to patch four specific vulnerabilities right now: CVE-2026-32201, CVE-2026-45659, CVE-2026-56164, and CVE-2026-58644. All four are confirmed as actively exploited, not theoretical risks. If your SharePoint server is exposed to the internet and unpatched, treat this as an active incident, not a maintenance task.

That’s the whole story in two sentences. Everything below is the “why” and the “how,” because a patch order without reasoning is just a to-do list you’ll ignore.

Why This Keeps Happening to SharePoint Specifically

SharePoint is not just a file share. It’s the connective tissue of a lot of corporate networks — intranets, document repositories, workflow automation, single sign-on integrations. That makes it an unusually rich target. Compromise one SharePoint server and you often get a map of the whole organization, not just a folder of PDFs.

This isn’t SharePoint’s first rodeo, either. Security researchers have pointed to the 2025 “ToolShell” campaign, a mass exploitation event, as the template attackers are now iterating on. Once a class of vulnerability proves profitable, criminal and state-linked groups keep probing nearby code paths for the next variant. That’s exactly what’s happening here: a steady drumbeat of related flaws, some caught before wide abuse, some not.

The Four Vulnerabilities, Ranked By How Much You Should Panic

Not all “critical” vulnerabilities are equally urgent. Here’s the practical breakdown.

CVE-2026-56164 — unauthenticated privilege escalation. This is the scariest category of bug because the attacker needs zero credentials to start. It’s a missing-authentication flaw, meaning the software simply forgets to check who’s asking before handing over sensitive functions. CISA added it to the Known Exploited Vulnerabilities (KEV) catalog on July 14, 2026, and gave federal agencies only three days to fix it. Three days is not a normal timeline. It’s a signal that the agency has seen real damage.

CVE-2026-58644 — remote code execution via deserialization, CVSS 9.8. This one requires an attacker to already have Site Owner-level access, which sounds like a mitigating factor until you remember how often internal accounts get phished or reused. Microsoft has confirmed this was exploited as a zero-day, meaning attackers were using it before a patch existed. That’s a meaningfully worse situation than a bug found by a researcher first.

CVE-2026-45659 — remote code execution, CVSS 8.8, also a deserialization bug. Patched back in May 2026 through an out-of-band update, which itself tells you Microsoft considered it too urgent to wait for the normal Patch Tuesday cycle. Attackers didn’t need much technical sophistication to weaponize it, according to Microsoft’s own advisory language, which is corporate-speak for “assume script kiddies can do this too.”

CVE-2026-32201 — the oldest of the four, added to KEV back in April 2026. If you haven’t patched this by now, the honest read is that patching isn’t part of your regular operations, and that’s a bigger problem than any single CVE.

Why “We’ll Patch It Next Cycle” Is the Wrong Instinct Here

Most vulnerability management runs on a monthly rhythm. Patch Tuesday comes, IT tests updates, they roll out over a few weeks. That cadence works fine for the bulk of routine bugs.

It does not work for anything on CISA’s KEV list. Inclusion in KEV specifically means the agency has evidence of real-world exploitation, not just theoretical risk. Under Binding Operational Directive 26-04, federal civilian agencies are legally required to patch KEV-listed flaws on an accelerated timeline, sometimes within days. Private organizations aren’t bound by that directive, but the underlying logic still applies to everyone: if a vulnerability is already being used in attacks, your risk clock started before you even read this article.

There’s also a numbers problem worth sitting with. Security researchers at Shadowserver have tracked roughly 10,000 SharePoint servers exposed directly to the internet, with hundreds still unpatched against known flaws. Attackers don’t need to target you specifically. They scan the whole internet for exposed, vulnerable servers and work through the list. Obscurity isn’t protection here.

What Attackers Actually Do Once They’re In

This part matters because it changes what “patched” even means. In several of these campaigns, attackers didn’t just gain access and leave — they stole Internet Information Services (IIS) machine keys. Those keys let an attacker forge trusted requests even after the original vulnerability gets patched. Patching closes the front door. It doesn’t necessarily evict someone who already stole a key while the door was open.

That’s the uncomfortable part of this story. If your server was exposed and unpatched for any meaningful window, patching alone may not be enough.

A Practical Checklist, Not Just a Patch List

  • Patch all four CVEs, prioritizing CVE-2026-56164 first since it needs no authentication at all.
  • Rotate IIS machine keys after patching if the server was ever internet-exposed during the vulnerable window. This closes the persistence loophole attackers rely on.
  • Enable Windows Antimalware Scan Interface (AMSI) for SharePoint web applications. CISA specifically calls this out because it lets Defender inspect scripts in memory before they execute, catching attacks that file-based scanning misses.
  • Check exposure, not just patch status. An unpatched internal-only server is a different risk tier than one facing the open internet.
  • Shorten your patch cycle for SharePoint specifically. Treat it like the crown-jewel system it functions as, not like a routine line-of-business app.

The Bigger Pattern Worth Remembering

None of this is really about SharePoint being uniquely bad software. It’s about SharePoint being uniquely central. Any system that sits at the intersection of documents, identity, and workflow automation will keep attracting this level of attention, patch after patch, year after year.

The organizations that stay ahead of it aren’t the ones with the fastest patch — they’re the ones who assume every KEV listing is a live fire drill rather than a line item. That mindset shift costs nothing and saves everything.

For the latest guidance and exact remediation deadlines, check CISA’s alert directly at cisa.gov rather than relying on secondhand summaries, since these advisories get updated as new exploitation details emerge.
